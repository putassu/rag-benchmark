# Система для бенчмарка и тюнинга RAG

Платформа для создания эталонных датасетов (Golden Datasets), разметки документов и автоматизированного тестирования Retrieval-Augmented Generation (RAG) пайплайнов.

## 📌 Архитектура

Текущая версия системы (MVP) разделена на два контура хранения:
1. **Qdrant (Векторная БД):** Хранение текстовых чанков, их метаданных (source, index) и эмбеддингов. Выступает как Single Source of Truth для текстовых фрагментов.
2. **SQLite (Реляционная БД):** Хранение бизнес-логики (пользователи, статусы документов, разметка QA-пар, веса релевантности чанков). *В будущих релизах планируется миграция на PostgreSQL.*
3. **FastAPI + Uvicorn:** Высокопроизводительный асинхронный бэкенд.

## 🚀 Быстрый старт (Docker)

Система разворачивается через `docker-compose`, что гарантирует персистентность данных (база и документы маунтятся в локальные директории сервера).

### 1. Подготовка окружения
Клонируйте репозиторий и создайте файл `.env` в корне проекта:

```env
OPENWEB_URL=http://your-openweb-url:8080
OPENWEB_API_KEY=sk-your-token
QDRANT_URL=http://your-qdrant-url:6333
QDRANT_API_KEY=
SECRET_KEY=change_this_to_strong_jwt_secret
```

### 2. Запуск контейнеров

```bash
# Поднять приложение в фоновом режиме
docker-compose up -d --build
```
После запуска на хосте автоматически создадутся папки `server_data/` (для SQLite) и `server_docs/` (для загрузки файлов).

### 3. Инициализация датасета (Ingest)
Для загрузки документов в Qdrant и распределения задач между аналитиками, положите файлы в `server_docs/` и выполните скрипт внутри работающего контейнера:

```bash
docker exec -it rag-annotation-backend python ingest.py
```

## 📊 Инструкция для аналитиков данных

Веб-интерфейс доступен по адресу: `http://<server-ip>:8000/`

**Процесс разметки:**
1. Авторизуйтесь под своей учетной записью.
2. Выберите документ из очереди (статус "В процессе").
3. Введите вопрос, который мог бы задать бизнес-пользователь, и ключевую фразу.
4. Выберите один или несколько чанков в тексте, присвоив им вес:
   * **Основа (Score=2):** Чанк содержит прямой и полный ответ.
   * **Контекст (Score=1):** Чанк содержит полезный контекст, но не является исчерпывающим ответом.
5. Нажмите "Сохранить". После завершения работы с файлом нажмите "Завершить документ".

### Выгрузка данных для локальных метрик
Для локального подсчета метрик (Recall@K, nDCG) администраторы могут выгрузить актуальную базу данных напрямую через API (без SSH-доступа к серверу):
* **Endpoint:** `GET /api/admin/export-db`
* **Auth:** Требуется Bearer токен администратора.
